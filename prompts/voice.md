# 写作风格备忘（来自本人语料）

> 来源：`elohia-double` 数字分身（本机 `D:\elohia`）——143.2 万条微信消息，本人发出 7.84 万条，2024-04 → 2026-10。
> 用途：写推文 / 回复 / 日报摘要时对齐语气。**分身只产草稿，不发**。

## 1 语料量出来的硬指标

| 指标 | 值 |
|:--|:--|
| 文本中位长度 | **7 字**（p90 = 22 字，平均 18.6） |
| 短句（≤8 字）占比 | **58%** |
| 长句（≥30 字）占比 | 7.3% |
| 表情标注率 | 8.4%（2026 年降到 4.2%） |
| 高频口头禅 | 好的×1107 · [捂脸]×526 · [旺柴]×448 · 对×386 · 哈哈哈×325 · 收到×297 · 嗯嗯×288 · ok×250 |
| 公开书写（朋友圈 21 条） | 40–80 字；贺词/纪念用文言对仗；日常极短 |

## 2 写推文的六条规则

1. **先短句，再展开**：第一句不超过 20 字，能一句话说完就不写第二句。
2. **说「写了个程序」**，不说「打造了一套工作流/体系/闭环」——语料里他原话就是「我写了个程序」「ai 写了个计算器」「一键发文章」。
3. **禁营销词**：赋能、闭环、抓手、重磅、炸裂、颠覆、史上最强、干货满满。
4. **数字必须真**：给不出的数字就删掉，不估、不凑。
5. **允许一处文言节奏**（如「动手之事另设七闸，默认皆闭」），但通篇文言就成了模仿秀。
6. **结尾不喊口号**：要么给链接，要么停住。

## 3 发布前的两道工序

```powershell
# 1) 用本人语气重写
node D:\elohia\scripts\assistant.mjs polish --text "<草稿>"
# 2) 体检像不像
node D:\elohia\scripts\assistant.mjs check --text "<草稿>"
```
`check` 的「长度」基准是**聊天语料中位 7 字**，所以 40 字左右也会被判「偏长」——
公开帖按 **40–80 字** 看，别照聊天基准压到 7 字，那就不像发帖了。

## 4 边界

语料含第三方隐私：只在本机用，不外传、不训练对外模型；草稿必须本人确认后才发。
